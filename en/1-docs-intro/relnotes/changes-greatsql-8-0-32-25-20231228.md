## Feature Enhancements

GreatSQL 8.0.32-25 introduces, for the first time, a high-performance in-memory query acceleration AP engine that can improve GreatSQL's data analysis performance by several orders of magnitude; greatly increases Oracle compatibility features, supporting more data types, SQL syntax, functions, and stored procedures; supports asynchronous deletion of large InnoDB tables; supports binding dynamic VIP to MGR read-only nodes and actively disconnecting current connections during primary switchover, shortening the application-side unavailability window.

### High Availability
- Supports binding VIP to read-only nodes in MGR Single Primary mode. Business traffic can access read-only nodes through the VIP, enabling dynamic VIP drift for read-only nodes. For more details, refer to: [MGR Dynamic VIP Binding](../../5-enhance/5-2-ha-mgr-vip.md).
- Supports actively closing current active connections when the primary node switches in MGR Single Primary mode, shortening the application-side unavailability window. For more details, refer to: [Disconnect Application Connections After MGR Primary Switchover](../../5-enhance/5-2-ha-mgr-kill-conn-after-switch.md).
- In cross-data-center disaster recovery scenarios, when multi-source replication and primary-primary bidirectional replication are enabled at the same time, data loop problems may occur. The new `replicate_server_mode` option is used to control applying only the binlog generated by the adjacent primary node in the multi-source replication pipeline, and not applying binlog generated by other non-adjacent nodes, avoiding data loop problems. Multi-channel primary-primary bidirectional replication can reduce source-replica configuration changes during data center disaster recovery drills and switchovers. This feature was contributed by the CMCC Smart Home DBA team (Xu Liang). For more details, refer to: [GreatSQL High Availability Feature - Loop Prevention in Primary-Primary Bidirectional Replication](../../5-enhance/5-2-ha-repl-server-mode.md).
- For more information, see the documentation: [High Availability](../../5-enhance/5-2-ha.md).

### High Performance
- Supports a large-scale parallel, high-performance in-memory query acceleration AP engine that can improve GreatSQL's data analysis performance by several orders of magnitude. In a 32C64G test machine environment, the total time of 22 SQL statements in the TPC-H 100G test is less than 80 seconds. For more details, refer to: [Rapid Engine](../../5-enhance/5-1-highperf-rapid-engine.md).

- Supports asynchronous deletion of large InnoDB tables. Deleting tables larger than 10G has almost no impact on system load, effectively improving the stability of InnoDB runtime performance. For more details, refer to: [Asynchronous Deletion of Large InnoDB Tables](../../5-enhance/5-1-highperf-async-purge-big-table.md).

- Improved InnoDB PQ capabilities, supporting TPC-H Q21 query optimization.

- For more information, see the documentation: [High Performance](../../5-enhance/5-1-highperf.md).

### High Compatibility
- Starting from GreatSQL 8.0.32-25, there has been a huge improvement in Oracle compatibility. In addition to OCI, DBlink, and Packages, most commonly used SQL syntax, data types, functions, stored procedures, triggers, and views are supported. Data types such as CLOB, NUMBER, VARCHAR2, and PLS_INTEGER are supported; functions such as ADD_MONTHS, CHR, and DUMP are supported; SQL syntax such as ANY, ALL, Hierarchical Query, and FULL JOIN is supported; and compatibility for stored procedures, triggers, and views is supported.

- For more information, see the documentation: [High Compatibility](../../5-enhance/5-3-easyuse.md).


## Bug Fixes

- Fixed the issue where the ARP table needs to be manually refreshed after binding VIP to MGR read/write nodes in a multi-subnet environment [issue#I7F3PB](https://gitee.com/GreatSQL/GreatSQL/issues/I7F3PB).
- Fixed the issue of very poor performance when executing encrypted CLONE backup if the receiving instance sets `innodb_flush_method = O_DIRECT`.
- Fixed the issue where TPC-H Q3 and Q5 query performance decreased after enabling the InnoDB PQ feature.
- Fixed the issue where the Oracle-compatible functions SUBSTR and SUBSTRB round the input parameters automatically in a way inconsistent with Oracle's handling.
- Fixed the issue where parallel LOAD DATA cannot correctly split complex text, and long transactions that are not committed cause continuous UNDO growth.
- Fixed the issue where when ROWNUM is used in a FOR LOOP, in each loop iteration, ROWNUM in the query result set cannot be reset to start from 0 again.
