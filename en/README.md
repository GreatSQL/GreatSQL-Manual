## About GreatSQL

GreatSQL is an **open-source and free** database that meets the requirements of financial-grade
application scenarios on commodity hardware. It features **High Availability**, **High Performance**,
**High Compatibility** and **High Security**, and can serve as an ideal drop-in replacement for
MySQL or Percona Server for MySQL.

## Core Features

### [High Availability](./5-enhance/5-2-ha.md)

GreatSQL makes extensive improvements and enhancements to MGR (Group Replication) and
primary-secondary replication, supporting features such as zone tags, arbitrator nodes,
dynamic read/write VIP, fast single-primary mode, and smart primary election. In addition,
it deeply optimizes several underlying MGR working mechanisms and algorithms, including the
flow control algorithm, the transaction certification queue cleanup algorithm, the node
join/leave mechanism, the recovery mechanism, and large transaction transfer compression,
further improving the high availability guarantee and performance stability of MGR.

- Supports the [zone tag](./5-enhance/5-2-ha-mgr-zoneid.md) feature to improve data reliability in multi-data-center architectures.
- Supports the [arbitrator node](./5-enhance/5-2-ha-mgr-arbitrator.md) feature to achieve higher availability at lower server cost.
- Supports the [dynamic read/write VIP](./5-enhance/5-2-ha-mgr-vip.md) feature, making high availability switchover more convenient and achieving read load balancing faster. Supports [proactively disconnecting active connections when the primary node is switched](./5-enhance/5-2-ha-mgr-kill-conn-after-switch.md) to shorten application unavailability time.
- Supports the [fast single-primary mode](./5-enhance/5-2-ha-mgr-fast-mode.md), which is faster and delivers higher performance in single-primary mode.
- Supports the [smart primary election](./5-enhance/5-2-ha-mgr-election-mode.md) feature, making the primary election mechanism in high availability switchover more reasonable.
- Optimizes the [flow control algorithm](./5-enhance/5-2-ha-mgr-new-fc.md) to make transactions more stable and avoid severe jitter.
- Supports [recording events when MGR network communication overhead exceeds the threshold](./5-enhance/5-2-ha-mgr-request-time.md) for further analysis and optimization.
- Supports automatically selecting the member node with the most recent transaction data as the data source, effectively improving Clone speed and enhancing MGR service reliability.
- In primary-secondary replication, supports rate limiting when a secondary node issues Binlog read requests to the primary node.
- Optimizes the [fault detection efficiency in asynchronous connection failover](https://dev.mysql.com/doc/refman/8.0/en/replication-asynchronous-connection-failover.html), reducing the time the primary-secondary replication link is disconnected and improving overall availability.
- Supports the [loop prevention mechanism in primary-primary bidirectional replication](./5-enhance/5-2-ha-repl-server-mode.md) in cross-data-center disaster recovery scenarios.
- Optimizes the severe performance jitter that may occur when MGR nodes join or leave.
- Resolves the issue where the entire MGR cluster is blocked when an individual node's disk becomes full.
- Optimizes the MGR transaction certification queue cleanup algorithm, eliminating the 60-second performance jitter under high load.
- Resolves the issue where long transactions in MGR prevent primary election.
- Fixes the long-waiting issue during the MGR recovery process.
- Optimizes the handling mechanism when compression exceeds the limit during large transaction transfer in MGR.

For more information, see: [High Availability](./5-enhance/5-2-ha.md).

### [High Performance](./5-enhance/5-1-highperf.md)

Compared with MySQL and Percona Server for MySQL, GreatSQL delivers more stable and superior
performance. It supports the Rapid Engine, Turbo Engine, lock-free transactions, parallel
LOAD DATA, asynchronous deletion of large tables, thread pool, non-blocking DDL, NUMA
affinity scheduling optimization, and more. In [TPC-C benchmarks it outperforms MySQL by
more than 30%](./10-optimize/3-5-benchmark-greatsql-vs-mysql-tpcc-report.md), and in
[TPC-H benchmarks its performance is ten to even a hundred times that of MySQL](./10-optimize/3-3-benchmark-greatsql-tpch-report.md).

- Supports the [high-performance Rapid Engine with massively parallel, in-memory queries and a high compression ratio](./5-enhance/5-1-highperf-rapid-engine.md), which can improve data analysis performance by several orders of magnitude.
- Supports the [high-performance parallel query engine Turbo](./5-enhance/5-1-highperf-turbo-engine.md), giving GreatSQL multi-threaded concurrent vectorized real-time query capabilities.
- Optimizes the InnoDB transaction system with multiple optimizations such as big-lock splitting and lock-free design, improving overall OLTP performance by about 20%.
- Supports [parallel LOAD DATA](./5-enhance/5-1-highperf-parallel-load.md), suitable for scenarios that frequently import large batches of data, with performance improvements of over 20x; it also provides optimizations for scenarios without an explicitly defined primary key.
- Supports [asynchronous deletion of large tables](./5-enhance/5-1-highperf-async-purge-big-table.md) to improve the runtime performance stability of the InnoDB engine.
- Supports the [thread pool](./5-enhance/5-1-highperf-thread-pool.md), reducing the cost of thread creation and destruction and ensuring stable performance under high concurrency without obvious degradation.
- Supports [non-blocking DDL](./5-enhance/5-1-highperf-nonblocking-ddl.md), avoiding the problem of business requests being massively blocked because the database must complete DDL operations as quickly as possible.
- Supports [NUMA affinity optimization](./5-enhance/5-1-highperf-numa-affinity.md). Through NUMA affinity scheduling, front-end user threads and background threads are bound to fixed NUMA nodes to improve thread processing performance.

For more information, see: [High Performance](./5-enhance/5-1-highperf.md).

### [High Compatibility](./5-enhance/5-3-easyuse.md)

GreatSQL is 100% compatible with the syntax of MySQL and Percona Server for MySQL, and
supports most common Oracle syntax, including [data type compatibility](./5-enhance/5-3-easyuse.md#data-type-compatibility),
[function compatibility](./5-enhance/5-3-easyuse.md#function-compatibility),
[SQL syntax compatibility](./5-enhance/5-3-easyuse.md#sql-syntax-compatibility),
[stored routine compatibility](./5-enhance/5-3-easyuse.md#stored-routine-compatibility),
and many other compatible extensions.

For more information, see: [High Compatibility](./5-enhance/5-3-easyuse.md).

### [High Security](./5-enhance/5-4-security.md)

GreatSQL supports multiple security enhancements, including logical backup encryption,
CLONE backup encryption, auditing, tablespace encryption with national cryptographic (GM)
algorithms, sensitive data masking, and login history storage, further safeguarding business
data and making it more suitable for financial-grade application scenarios.

- Supports [mysqldump logical backup encryption](./5-enhance/5-4-security-mysqldump-encrypt.md), providing secure encryption for mysqldump logical backups.
- Supports [Clone backup encryption](./5-enhance/5-4-security-clone-encrypt.md), providing secure encryption for Clone physical backups.
- Supports the [auditing feature](./5-enhance/5-4-security-audit.md), recording and detecting unauthorized or unsafe behavior in a timely manner.
- Supports [InnoDB tablespace encryption with national cryptographic (GM) algorithms](./5-enhance/5-4-security-encrypt-with-gmssl.md), ensuring the encryption security of important data.
- Supports [two data masking approaches based on functions and policies](./5-enhance/5-4-security-data-masking.md), protecting the confidentiality of query results for sensitive user data.

Through the above security enhancements, business data security is further safeguarded.
For more information, see: [High Security](./5-enhance/5-4-security.md).

### [Others](./5-enhance/5-5-others.md)

- Supports [Clone online full hot backup, incremental backup and recovery](./5-enhance/5-5-clone-compressed-and-incrment-backup.md); combined with Binlog, it can restore to a specified point in time. In addition, Clone backups support compression.
- Supports [InnoDB Page transparent compression using the Zstd algorithm](./5-enhance/5-5-innodb-page-compression.md), further improving the data compression ratio, especially when there is a large amount of repeated long-text data.

## Installing GreatSQL

### Install jemalloc (Recommended)

Running GreatSQL with jemalloc support makes the memory allocation of the database process
more stable and efficient, so it is recommended to install jemalloc (not mandatory).

On ARM environments, it is not necessary to install and configure the jemalloc dependency.

Taking a CentOS 8 x86_64 system as an example, install the jemalloc package as follows:

```bash
# First install the EPEL repository
yum install -y epel-release

# Then install jemalloc
yum -y install jemalloc jemalloc-devel
```

You can also add the path of a self-compiled dynamic library (so file) to the system
configuration file, for example:

```bash
cat /etc/ld.so.conf
/usr/local/lib64/
```

Then run the following commands to load the libjemalloc library and verify that it exists:

```bash
ldconfig && ldconfig -p | grep libjemalloc
```

::: details View the output
```bash
$ ldconfig && ldconfig -p | grep libjemalloc

...
        libjemalloc.so.1 (libc6,x86-64) => /usr/local/lib64/libjemalloc.so.1
        libjemalloc.so (libc6,x86-64) => /usr/local/lib64/libjemalloc.so
```
:::

If jemalloc cannot be installed directly via yum, you can download the RPM package yourself
from: [https://centos.pkgs.org/8/epel-x86_64/jemalloc-5.2.1-2.el8.x86_64.rpm.html](https://centos.pkgs.org/8/epel-x86_64/jemalloc-5.2.1-2.el8.x86_64.rpm.html)

### Download and Install GreatSQL

Installing the GreatSQL RPM packages is recommended.

[Click here to download the GreatSQL RPM packages](https://gitee.com/GreatSQL/GreatSQL/releases/GreatSQL-8.4.4-4).

Taking a CentOS 8 system as an example, install GreatSQL with commands similar to the following:

```bash
# First, check whether GreatSQL is already installed
yum search greatsql
...
No matches found.

# Then install
rpm -ivh --nodeps greatsql-client-8.4.4-4.1.el8.x86_64.rpm greatsql-devel-8.4.4-4.1.el8.x86_64.rpm greatsql-icu-data-files-8.4.4-4.1.el8.x86_64.rpm greatsql-server-8.4.4-4.1.el8.x86_64.rpm greatsql-shared-8.4.4-4.1.el8.x86_64.rpm
```

::: tip Tip

When formally installing the GreatSQL RPM packages, other packages such as openssl and Perl
may also be required as dependencies. For a quick demonstration, the `--nodeps` parameter is
used here to skip the dependency checks. If the service fails to start after installation due
to missing dependencies, please install the corresponding dependency packages.
:::

After installation, GreatSQL completes initialization automatically. You can check whether
it has been registered as a system service or has started:

```bash
systemctl status mysqld
```

::: details View the output
```bash

...
```

The GreatSQL service can then be started normally.

For more efficient operation of GreatSQL, it is recommended to refer to this my.cnf
configuration template: [my.cnf for GreatSQL 8.4.4-4](https://gitee.com/GreatSQL/GreatSQL-Doc/blob/master/docs/my.cnf-example-greatsql-8.4.4-4).

### Compiling GreatSQL from Source

If you want to compile binary packages from the GreatSQL source code, you can use the
GreatSQL-Build Docker image. See: [GreatSQL-Build Docker image](https://gitee.com/GreatSQL/GreatSQL-Docker/tree/master/GreatSQL-Build).

If you want to compile the GreatSQL source code manually, you can refer to the following documents:

- [Compile and install GreatSQL from source on CentOS](https://gitee.com/GreatSQL/GreatSQL-Doc/blob/master/docs/build-greatsql-with-source.md)
- [Build GreatSQL RPM packages on CentOS](https://gitee.com/GreatSQL/GreatSQL-Doc/blob/master/docs/build-greatsql-rpm-under-centos.md)
- [Build GreatSQL binary packages on openEuler, Anolis, and UOS](https://gitee.com/GreatSQL/GreatSQL-Doc/blob/master/docs/build-greatsql-under-openeuler-anolis-uos.md)
- [Compile and install GreatSQL from source on Kylin OS + Loongson](https://gitee.com/GreatSQL/GreatSQL-Doc/blob/master/docs/build-greatsql-with-source-under-kylin-and-loongson.md)

**Note**: You need to download the [GreatSQL source package](https://gitee.com/GreatSQL/GreatSQL/releases)
for compilation, rather than compiling the source code obtained by directly `git clone`-ing
this repository, because some submodule code is missing.
