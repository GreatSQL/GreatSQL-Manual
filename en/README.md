## About GreatSQL

GreatSQL is an **open-source and free** database that meets the requirements of financial-grade
application scenarios on commodity hardware. It features **High Availability**, **High Performance**,
**High Compatibility** and **High Security**, and can serve as an ideal drop-in replacement for
MySQL or Percona Server for MySQL.

## Core Features

### [High Availability](./5-enhance/5-2-ha.md)

GreatSQL makes many improvements and enhancements to MGR (Group Replication) and primary-secondary
replication. It supports zone tags, arbitrator nodes, dynamic read/write VIP, fast single-primary
mode, smart primary election, and deeply optimizes several underlying MGR mechanisms and algorithms
— including flow control, transaction certification queue cleanup, node join/leave mechanisms,
recovery mechanisms, and large transaction transfer compression — further improving MGR
high-availability guarantees and performance stability.

- Supports [zone tags](./5-enhance/5-2-ha-mgr-zoneid.md), improving data reliability in multi-datacenter architectures.
- Supports [arbitrator nodes](./5-enhance/5-2-ha-mgr-arbitrator.md), achieving higher availability at lower server cost.
- Supports [dynamic read/write VIP](./5-enhance/5-2-ha-mgr-vip.md), making high-availability failover more convenient and read load balancing faster. Supports [actively terminating active connections when the primary node fails over](./5-enhance/5-2-ha-mgr-kill-conn-after-switch.md), shortening the application-side downtime.
- Supports [fast single-primary mode](./5-enhance/5-2-ha-mgr-fast-mode.md), which is faster and more performant in single-primary mode.
- Supports [smart primary election](./5-enhance/5-2-ha-mgr-election-mode.md), making the failover primary election mechanism more reasonable.
- Optimizes the [flow control algorithm](./5-enhance/5-2-ha-mgr-new-fc.md) to make transactions smoother and avoid severe jitter.
- Supports [recording events where MGR network communication overhead exceeds a threshold](./5-enhance/5-2-ha-mgr-request-time.md), for further analysis and optimization.
- Supports automatically selecting the member node with the most up-to-date transaction data for cloning, effectively improving Clone speed and MGR service reliability.
- In primary-secondary replication, supports rate limiting when a secondary node requests Binlog reads from the primary node.
- Optimizes fault detection efficiency in [asynchronous connection failover](https://dev.mysql.com/doc/refman/8.0/en/replication-asynchronous-connection-failover.html), reducing replication link downtime and improving overall availability.
- Supports a [loop-prevention mechanism for primary-primary bidirectional replication](./5-enhance/5-2-ha-repl-server-mode.md) in cross-datacenter disaster recovery scenarios.
- Compatible with the full set of legacy replication syntax — [`CHANGE MASTER TO`, `START SLAVE`, etc. — along with their status variables and error messages](./5-enhance/5-2-ha-repl-interface-cmd.md). This resolves the errors caused by old replication management statements after upgrading from lower versions to 8.4, greatly reducing the workload of major version upgrades.
- Optimizes the severe performance jitter that could occur when MGR nodes join or leave.
- Fixes the issue where the entire MGR cluster could be blocked when disk space on one node runs out.
- Optimizes the MGR transaction certification queue cleanup algorithm; the performance jitter every 60 seconds under high load no longer occurs.
- Fixes the issue where long transactions in MGR could prevent primary election.
- Fixes the long wait issue during MGR recovery.
- Optimizes the handling mechanism when large transaction transfer compression exceeds the limit in MGR.

See the [High Availability](./5-enhance/5-2-ha.md) document for more details.

### [High Performance](./5-enhance/5-1-highperf.md)

Compared with MySQL and Percona Server for MySQL, GreatSQL delivers more stable and better
performance. It supports the Rapid Engine, Turbo Engine, lock-free transactions, parallel
LOAD DATA, asynchronous large-table drops, thread pool, non-blocking DDL, NUMA affinity
scheduling optimization and more. In [TPC-C benchmarks, performance is improved by over 30% compared with MySQL](./10-optimize/3-5-benchmark-greatsql-vs-mysql-tpcc-report.md), and in [TPC-H benchmarks it is dozens or even hundreds of times faster than MySQL](./10-optimize/3-3-benchmark-greatsql-tpch-report.md).

- Supports the [Rapid Engine — massively parallel, memory-based queries with a high compression ratio](./5-enhance/5-1-highperf-rapid-engine.md), which can improve data analytics performance by several orders of magnitude.
- Supports the [Turbo high-performance parallel query engine](./5-enhance/5-1-highperf-turbo-engine.md), giving GreatSQL multi-threaded, concurrent, vectorized real-time query capability. It also supports [vector similarity search with the Turbo Engine](./5-enhance/5-1-highperf-vector-search.md).
- Supports [independent flush optimization for large-transaction binlog](./5-enhance/5-1-highperf-binlog-flush-opt-large-trx.md), which can **reduce large-transaction commit latency by 30%–70% and improve high-concurrency TPS by 10%–40%**, ensuring system stability.
- Optimizes the [parallel replica replay mechanism on secondary nodes in primary-secondary/group replication](./5-enhance/5-1-highperf-parallel-replica.md), effectively reducing scheduling stalls, increasing secondary-side parallel replay throughput, lowering replication lag, and strengthening cluster high-availability stability.
- Supports [execution plan change anomaly detection at the SQL Digest level](./5-enhance/5-1-highperf-execplan-baseline.md), continuously collecting and caching execution plan baseline information, identifying plan changes and suspicious SQL through differential comparison, and solving problems such as invisible execution plan drift after database restart/upgrade.
- Optimizes the InnoDB transaction system with large-lock splitting and lock-free designs, improving overall OLTP performance by about 20%.
- Supports [parallel LOAD DATA](./5-enhance/5-1-highperf-parallel-load.md), suitable for applications that frequently import large volumes of data, with performance gains of about 20×; there are also optimizations for tables without an explicitly defined primary key.
- Supports [asynchronous deletion of large tables](./5-enhance/5-1-highperf-async-purge-big-table.md), improving the runtime stability of the InnoDB engine.
- Supports [thread pool](./5-enhance/5-1-highperf-thread-pool.md), reducing the cost of thread creation and destruction and keeping performance stable without significant degradation under high concurrency.
- Supports [non-blocking DDL](./5-enhance/5-1-highperf-nonblocking-ddl.md), avoiding large numbers of business requests being blocked because DDL must complete as quickly as possible.
- Supports [NUMA affinity optimization](./5-enhance/5-1-highperf-numa-affinity.md), binding front-end user threads and background threads to fixed NUMA nodes to improve thread processing performance.

See the [High Performance](./5-enhance/5-1-highperf.md) document for more details.

### [High Compatibility](./5-enhance/5-3-easyuse.md)

GreatSQL is 100% compatible with MySQL and Percona Server for MySQL syntax and supports most
common Oracle syntax, including [data type compatibility](./5-enhance/5-3-easyuse.md#data-type-compatibility),
[function compatibility](./5-enhance/5-3-easyuse.md#function-compatibility),
[SQL syntax compatibility](./5-enhance/5-3-easyuse.md#sql-syntax-compatibility) and
[stored routine compatibility](./5-enhance/5-3-easyuse.md#stored-routine-compatibility),
along with many other extended compatibility features.

See the [High Compatibility](./5-enhance/5-3-easyuse.md) document for more details.

### [High Security](./5-enhance/5-4-security.md)

GreatSQL supports multiple security enhancement features — logical backup encryption, CLONE
backup encryption, auditing, GMSSL national cryptography tablespace encryption, sensitive data
masking, login history storage, and more — further protecting business data and making GreatSQL
better suited to financial-grade application scenarios.

- Supports [mysqldump logical backup encryption](./5-enhance/5-4-security-mysqldump-encrypt.md), meeting the encryption requirements of logical backups with mysqldump.
- Supports [Clone backup encryption](./5-enhance/5-4-security-clone-encrypt.md), meeting the encryption requirements of physical backups with Clone.
- Supports [auditing](./5-enhance/5-4-security-audit.md), promptly recording and detecting unauthorized or unsafe behavior.
- Supports [GMSSL national cryptography encryption for InnoDB tablespaces](./5-enhance/5-4-security-encrypt-with-gmssl.md), ensuring encrypted security of important data.
- Supports [two data masking approaches based on functions and policies](./5-enhance/5-4-security-data-masking.md), protecting the confidentiality of query results for sensitive user data.

Through the security enhancement features above, business data security is further protected.
See the [High Security](./5-enhance/5-4-security.md) document for more details.

### [Others](./5-enhance/5-5-others.md)
- Supports [Clone online full hot backup, incremental backup and recovery](./5-enhance/5-5-clone-compressed-and-incrment-backup.md); combined with Binlog, recovery to a specified point in time is possible. In addition, Clone backups support compression.
- Supports [InnoDB Page transparent compression using the Zstd algorithm](./5-enhance/5-5-innodb-page-compression.md), further improving the data compression ratio, especially when there is a large amount of duplicated long-text data.
- Supports the **mysqlbinlog display of the actual number of affected rows** feature: with the `-vvv` option, the output of `mysqlbinlog` additionally shows the actual `affected rows` per transaction, enhancing the observability of binlog parsing and operational statistics.

## Install GreatSQL

### Install jemalloc (Recommended)

When jemalloc support is available, the memory allocation of the database process is more stable
and efficient, so installing jemalloc is recommended (though not mandatory).

On ARM environments, installing and configuring the jemalloc dependency is unnecessary.

Taking CentOS 8 x86_64 as an example, install the jemalloc package as follows:

```bash
# First install the EPEL repository
yum install -y epel-release

# Then install jemalloc
yum -y install jemalloc jemalloc-devel
```

You can also add the path of a self-installed dynamic library (.so) file to the system
configuration file, for example:

```bash
cat /etc/ld.so.conf
/usr/local/lib64/
```

Then run the following commands to load the libjemalloc library and verify it exists:

```bash
ldconfig && ldconfig -p | grep libjemalloc
```

::: details View the output
```bash
$ ldconfig && ldconfig -p | grep libjemalloc

...
        libjemalloc.so.1 (libc6,x86-64) => /usr/local/lib64/libjemalloc.so.1
        libjemalloc.so (libc6,x86-64) => /usr/local/lib64/libjemalloc.so
```
:::

If jemalloc cannot be installed directly via yum, you can download the RPM package yourself:
[https://centos.pkgs.org/8/epel-x86_64/jemalloc-5.2.1-2.el8.x86_64.rpm.html](https://centos.pkgs.org/8/epel-x86_64/jemalloc-5.2.1-2.el8.x86_64.rpm.html)

### Download and Install GreatSQL

Installing the GreatSQL RPM package is recommended.

[Click this link to download the GreatSQL RPM package](https://gitee.com/GreatSQL/GreatSQL/releases/GreatSQL-8.4.4-5).

Taking CentOS 8 as an example, install GreatSQL with commands similar to the following:

```bash
# First, check whether GreatSQL is already installed
yum search greatsql
...
No matches found.

# Then install
rpm -ivh --nodeps greatsql-client-8.4.4-5.1.el8.x86_64.rpm greatsql-devel-8.4.4-5.1.el8.x86_64.rpm greatsql-icu-data-files-8.4.4-5.1.el8.x86_64.rpm greatsql-server-8.4.4-5.1.el8.x86_64.rpm greatsql-shared-8.4.4-5.1.el8.x86_64.rpm
```

::: tip Tip

When installing the GreatSQL RPM package for real, additional packages such as openssl and Perl
may be required. This is only a quick demonstration, so the `--nodeps` parameter is used to skip
the dependency checks. If the service cannot start after installation due to missing dependencies,
install the required dependency packages accordingly.
:::

After installation, GreatSQL completes initialization by itself. You can then check whether it
has been registered as a system service or has already started:

```bash
systemctl status mysqld
```

::: details View the output
```bash
$ systemctl status mysqld
```

The GreatSQL service can now start normally.

For more efficient GreatSQL operation, it is recommended to refer to this my.cnf configuration
