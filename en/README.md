## About GreatSQL

GreatSQL is an **open-source and free** database that can meet the requirements of financial-grade application scenarios on commodity hardware. With features such as **High Availability**, **High Performance**, **High Compatibility** and **High Security**, it can serve as an ideal drop-in replacement for MySQL or Percona Server for MySQL.

## GreatSQL Core Features

### [High Availability](./5-enhance/5-2-ha.md)

GreatSQL has made extensive improvements and enhancements to MGR and primary-secondary replication, supporting features such as **zone tags**, **arbitrator nodes**, **dynamic read/write VIP**, **fast single-primary mode** and **smart primary election**. It also deeply optimizes multiple underlying MGR working mechanisms and algorithms, including the flow control algorithm, transaction certification queue cleanup algorithm, node join & leave mechanism, recovery mechanism, and large transaction transfer compression, further strengthening MGR's high availability guarantees and performance stability.

- Supports the [zone tags](./5-enhance/5-2-ha-mgr-zoneid.md) feature, improving data reliability in multi-datacenter architectures.
- Supports the [arbitrator node](./5-enhance/5-2-ha-mgr-arbitrator.md) feature, achieving higher availability at lower server cost.
- Supports the [dynamic read/write VIP](./5-enhance/5-2-ha-mgr-vip.md) feature, making high availability switchovers more convenient and read load balancing faster. Supports [proactively closing the currently active connections when the primary node switches](./5-enhance/5-2-ha-mgr-kill-conn-after-switch.md), reducing the application-side unavailable time.
- Supports the [fast single-primary mode](./5-enhance/5-2-ha-mgr-fast-mode.md), which is faster and delivers higher performance in single-primary mode.
- Supports the [smart primary election](./5-enhance/5-2-ha-mgr-election-mode.md) feature, making the primary election mechanism during high availability switchover more reasonable.
- Optimizes the [flow control algorithm](./5-enhance/5-2-ha-mgr-new-fc.md), making transactions steadier and avoiding severe jitter.
- Supports [recording events where MGR network communication overhead exceeds a threshold](./5-enhance/5-2-ha-mgr-request-time.md), for further analysis and optimization.
- Supports automatically choosing the member node with the latest transaction data to replicate from, which effectively improves Clone speed and enhances MGR service reliability.
- In primary-secondary replication, supports rate limiting when a secondary node initiates Binlog read requests to the primary node.
- Optimizes the fault detection efficiency in [asynchronous connection failover](https://dev.mysql.com/doc/refman/8.0/en/replication-asynchronous-connection-failover.html), reducing the time the replication link is disconnected and improving overall availability.
- Supports the [loop prevention mechanism for primary-primary bidirectional replication](./5-enhance/5-2-ha-repl-server-mode.md) in cross-datacenter disaster recovery scenarios.
- Optimizes the problem of severe performance jitter that may occur when MGR nodes join or leave.
- Resolves the problem where the entire MGR cluster is blocked when the disk space on an individual node runs full.
- Optimizes the MGR transaction certification queue cleanup algorithm, so the performance jitter every 60 seconds under high load no longer occurs.
- Resolves the problem where long transactions in MGR prevent primary election.
- Fixes the problem of long waiting during MGR recovery.
- Optimizes the handling mechanism when compression exceeds the limit during large transaction transfer in MGR.

For more information, see the document: [High Availability](./5-enhance/5-2-ha.md).

### [High Performance](./5-enhance/5-1-highperf.md)

Compared with MySQL and Percona Server for MySQL, GreatSQL delivers more stable and superior performance. It supports the **Rapid Engine**, **Turbo Engine**, **lock-free transactions**, **parallel LOAD DATA**, **asynchronous deletion of large tables**, **thread pool**, **non-blocking DDL**, **NUMA affinity scheduling optimization** and other features. In [TPC-C benchmarks it outperforms MySQL by over 30%](./10-optimize/3-5-benchmark-greatsql-vs-mysql-tpcc-report.md), and in [TPC-H benchmarks its performance is dozens or even hundreds of times that of MySQL](./10-optimize/3-3-benchmark-greatsql-tpch-report.md).

- Supports the [high-performance Rapid Engine](./5-enhance/5-1-highperf-rapid-engine.md) with massive parallelism, in-memory queries and a high compression ratio, which can improve data analysis performance by several orders of magnitude.
- Supports the [high-performance parallel query engine Turbo](./5-enhance/5-1-highperf-turbo-engine.md), giving GreatSQL multi-threaded concurrent vectorized real-time query capabilities.
- Optimizes the InnoDB transaction system, implementing multiple optimization approaches such as splitting large locks and making them lock-free, improving overall OLTP performance by about 20%.
- Supports [parallel LOAD DATA](./5-enhance/5-1-highperf-parallel-load.md), suitable for application scenarios that frequently import large batches of data, with performance improved by about 20 times or more; it is also optimized for scenarios without an explicitly defined primary key.
- Supports [asynchronous deletion of large tables](./5-enhance/5-1-highperf-async-purge-big-table.md), improving the runtime performance stability of the InnoDB engine.
- Supports the [thread pool](./5-enhance/5-1-highperf-thread-pool.md), reducing the cost of thread creation and destruction, and ensuring stable performance without obvious degradation under high concurrency.
- Supports [non-blocking DDL](./5-enhance/5-1-highperf-nonblocking-ddl.md), avoiding the problem where a large number of business requests are blocked because the database must complete DDL operations as quickly as possible.
- Supports [NUMA affinity optimization](./5-enhance/5-1-highperf-numa-affinity.md), binding front-end user threads and background threads to fixed NUMA nodes through NUMA affinity scheduling optimization to improve thread processing performance.

For more information, see the document: [High Performance](./5-enhance/5-1-highperf.md).

### [High Compatibility](./5-enhance/5-3-easyuse.md)

GreatSQL is 100% fully compatible with MySQL and Percona Server for MySQL syntax, and supports most common Oracle syntax, including [Data Type Compatibility](./5-enhance/5-3-easyuse.md#data-type-compatibility), [Function Compatibility](./5-enhance/5-3-easyuse.md#function-compatibility), [SQL Syntax Compatibility](./5-enhance/5-3-easyuse.md#sql-syntax-compatibility), [Stored Routine Compatibility](./5-enhance/5-3-easyuse.md#stored-routine-compatibility) and many other compatible extension usages.

For more information, see the document: [High Compatibility](./5-enhance/5-3-easyuse.md).

### [High Security](./5-enhance/5-4-security.md)

GreatSQL supports logical backup encryption, Clone backup encryption, auditing, GM (national cryptography) tablespace encryption, sensitive data masking, and storage of login history, among many other security enhancement features, further protecting business data security and making it more suitable for financial-grade application scenarios.

- Supports [mysqldump logical backup encryption](./5-enhance/5-4-security-mysqldump-encrypt.md), meeting the secure encryption requirements of logical backups using mysqldump.
- Supports [Clone backup encryption](./5-enhance/5-4-security-clone-encrypt.md), meeting the secure encryption requirements of physical backups using Clone.
- Supports the [auditing feature](./5-enhance/5-4-security-audit.md), promptly recording and discovering unauthorized or unsafe behavior.
- Supports [GM (national cryptography) encryption algorithms for InnoDB tablespaces](./5-enhance/5-4-security-encrypt-with-gmssl.md), ensuring the encryption security of important data.
- Supports [two kinds of data masking based on functions and policies](./5-enhance/5-4-security-data-masking.md), keeping the query results of sensitive user data confidential.
- Supports [storing login history](./5-enhance/5-4-security-last-login.md), making it convenient for administrators to query and further improving database security.

Through the multiple security enhancement features above, business data security is further protected. For more information, see the document: [High Security](./5-enhance/5-4-security.md).

### [Others](./5-enhance/5-5-others.md)
- Supports [Clone online full hot backup, incremental backup and recovery](./5-enhance/5-5-clone-compressed-and-incrment-backup.md), and combined with Binlog, recovery to a specified point in time is possible. In addition, Clone backup also supports compression.
- Supports [InnoDB Page transparent compression using the Zstd algorithm](./5-enhance/5-5-innodb-page-compression.md), further improving the data compression ratio, especially when there is a large amount of long-text duplicate data.

## Installing GreatSQL

### Installing jemalloc (recommended)

When running GreatSQL with jemalloc support, the memory allocation of the database process is more stable and efficient, so it is recommended to install jemalloc (not mandatory).

On ARM environments, it is not necessary to install and configure the jemalloc dependency.

Taking CentOS 8 x86_64 as an example, install the jemalloc package as follows:

```bash
# First install the EPEL repository
yum install -y epel-release

# Then install jemalloc
yum -y install jemalloc jemalloc-devel
```

You can also add the path of a self-installed dynamic library so file to the system configuration file, for example:

```bash
cat /etc/ld.so.conf
/usr/local/lib64/
```

Then run the following commands to load the libjemalloc library and confirm whether it exists:

```bash
ldconfig && ldconfig -p | grep libjemalloc
```

::: details View the output
```bash
$ ldconfig && ldconfig -p | grep libjemalloc

...
        libjemalloc.so.1 (libc6,x86-64) => /usr/local/lib64/libjemalloc.so.1
        libjemalloc.so (libc6,x86-64) => /usr/local/lib64/libjemalloc.so
```
:::

If jemalloc cannot be installed directly via yum, you can download the RPM package yourself from: [https://centos.pkgs.org/8/epel-x86_64/jemalloc-5.2.1-2.el8.x86_64.rpm.html](https://centos.pkgs.org/8/epel-x86_64/jemalloc-5.2.1-2.el8.x86_64.rpm.html)

### Downloading and Installing GreatSQL

Installing the GreatSQL RPM package is recommended.

[Click here to download the GreatSQL RPM packages](https://gitee.com/GreatSQL/GreatSQL/releases/GreatSQL-8.0.32-27).

Taking CentOS 8 as an example, install GreatSQL with commands similar to the following:

```bash
# First, check whether GreatSQL is already installed
yum search greatsql
...
No matches found.

# Then install
rpm -ivh --nodeps greatsql-client-8.0.32-27.1.el8.x86_64.rpm greatsql-devel-8.0.32-27.1.el8.x86_64.rpm greatsql-icu-data-files-8.0.32-27.1.el8.x86_64.rpm greatsql-mysql-router-8.0.32-27.1.el8.x86_64.rpm greatsql-server-8.0.32-27.1.el8.x86_64.rpm greatsql-shared-8.0.32-27.1.el8.x86_64.rpm greatsql-test-8.0.32-27.1.el8.x86_64.rpm
```

::: tip Tip

When formally installing the GreatSQL RPM packages, dependencies on openssl, Perl and other packages may still be required. This is a quick demonstration, so the `--nodeps` parameter is added to skip the corresponding dependency checks. After installation, if the service cannot start due to missing dependencies, please install the corresponding software dependency packages.
:::

After installation, GreatSQL initializes itself automatically. You can then check whether it has been registered as a system service or has already started:

```bash
systemctl status mysqld
```
